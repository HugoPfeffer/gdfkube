## ADDED Requirements

### Requirement: REQ-003-01 Compose stack boots all required services

The file `gdfkube-src/compose.yaml`, generated by `score-compose generate -f score.node.yaml -f score.camel.yaml -f score-compose.yaml`, SHALL declare exactly these top-level services with the listed image pins: `mongo` (`mongo:7.0`), `kafka` (`apache/kafka:3.9`), `kafka-connect` (`quay.io/debezium/connect:3.0`), `gitea` (`gitea/gitea:1.22`), `node-dummy` (`nginxinc/nginx-unprivileged:1.27`), `camel-dummy` (`quay.io/quarkus/quarkus-micro-image:2.0`). Running `task dev:up` against this file MUST cause every service to reach Docker `Healthy` (or `Running` for services without a healthcheck) within 120 seconds on the project devcontainer.

#### Scenario: SCN-003-01-01 Stack converges within 2 min

- **GIVEN** a clean checkout where no compose stack is running (`docker compose ls` shows no `gdfkube-dev` project)
- **WHEN** `task dev:up` runs from `gdfkube-src/`
- **THEN** within 120 seconds `docker compose ps --format '{{.Name}}\t{{.State}}\t{{.Health}}'` MUST report each of the six services in state `running`, with `mongo` and `gitea` in health state `healthy`, and `task dev:up` MUST exit 0

#### Scenario: SCN-003-01-02 Image pin missing fails generation

- **GIVEN** `score-compose.yaml` omits the image-pin overlay for `mongo`
- **WHEN** `task score:gen` runs
- **THEN** the command MUST exit non-zero and stderr MUST contain a reference to the unpinned image; the prior `compose.yaml` on disk MUST remain untouched

### Requirement: REQ-003-02 Mongo replica-set initialization

The script `gdfkube-src/scripts/init-mongo.js` SHALL be mounted into the `mongo` service at `/docker-entrypoint-initdb.d/init-mongo.js` and SHALL invoke `rs.initiate()` so that Debezium oplog tailing succeeds on first boot. After initialization, `mongosh --quiet --eval 'rs.status().myState'` MUST return state code `1` (PRIMARY).

#### Scenario: SCN-003-02-01 Replica set initializes to PRIMARY

- **GIVEN** the `mongo` service has just transitioned to health `healthy`
- **WHEN** `docker compose exec mongo mongosh --quiet --eval 'rs.status().myState'` runs
- **THEN** stdout MUST equal `1` and the command MUST exit 0

#### Scenario: SCN-003-02-02 Init script absent fails health

- **GIVEN** the host file `gdfkube-src/scripts/init-mongo.js` is missing
- **WHEN** `task dev:up` runs
- **THEN** the `mongo` service MUST fail its healthcheck within the retry budget, `task dev:up` MUST exit non-zero, and `docker compose logs mongo` MUST contain a `not running with --replSet` or replica-set error line

### Requirement: REQ-003-03 Connector registration script

The script `gdfkube-src/scripts/register-connector.sh` SHALL be mounted at `/docker-entrypoint-init.d/register-connector.sh` inside the `kafka-connect` service and SHALL POST the contents of `/etc/connect/connector.json` (the in-container path of `gdfkube-src/connector.json`) to `http://localhost:8083/connectors`. On a fresh boot the connector named `gdfkube-mongo-source` MUST appear in the response of `GET /connectors` within 60 seconds of the `kafka-connect` service reaching `running`.

#### Scenario: SCN-003-03-01 Connector registers on boot

- **GIVEN** the compose stack has just converged
- **WHEN** `curl -fsS http://localhost:8083/connectors` runs from the devcontainer
- **THEN** the response body MUST contain the literal string `gdfkube-mongo-source` and the HTTP status MUST be `200`

#### Scenario: SCN-003-03-02 Connect API unreachable returns clear error

- **GIVEN** the `kafka-connect` service is in state `restarting`
- **WHEN** `register-connector.sh` runs and the REST API is unreachable
- **THEN** the script MUST retry with backoff up to 60 seconds, then exit non-zero with stderr message `register-connector: API at localhost:8083 unreachable after 60s`

### Requirement: REQ-003-04 Gitea local-dev init mirrors agnosticd Secret shape

The script `gdfkube-src/scripts/gitea-init.sh` SHALL run inside the `gitea` compose service to create an admin user and pre-create the `gdfkube-src` repository, then expose an admin token in a form that `score-compose` resolves to the env var `GITEA_TOKEN`. This mirrors the OpenShift contract where agnosticd provisions a `Secret` (`gdfkube-gitea-credentials`); under no circumstance MAY the script run against a non-local Gitea instance.

#### Scenario: SCN-003-04-01 Local Gitea exposes GITEA_TOKEN

- **GIVEN** the `gitea` service has converged on a fresh `task dev:up`
- **WHEN** `docker compose exec node-dummy printenv GITEA_TOKEN` runs
- **THEN** the command MUST exit 0 and stdout MUST be a non-empty token string

#### Scenario: SCN-003-04-02 Script refuses non-local target

- **GIVEN** `GITEA_URL` resolves to a host other than `gitea` (e.g., `gitea.example.com`)
- **WHEN** `gitea-init.sh` is executed
- **THEN** the script MUST exit non-zero before any HTTP request and stderr MUST contain `gitea-init: refuses non-local target` followed by the offending host
